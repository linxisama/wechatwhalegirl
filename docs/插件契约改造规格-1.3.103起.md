# 插件契约改造规格（1.3.103 起）

来源：用户 2026-11-08 给出的诊断结论与三条判定标准。

## 一、判定标准（用户原话，作为总纲）

判断标准不是「能放进 mods/ 就算」，有以下三条：

1. **是后来加的，不是原版内容换个包装。** 整合包不会把钻石剑、苦力怕列成 mod。
2. **有清单，能单独装、单独卸。** 删掉 jar，行为消失，不残留。
3. **不靠改原版内部实现活着。** 靠了也能装，但必须标出来，把代价写在明面上——那就是 Mixin 那条路。

## 二、当前实现的十条逐项现状（1.3.102 实测）

## 三、六批改造（每批一个版本号）

### 1.3.103 — manifest 契约升级（本批）

**问题**：13 个字段里 10 个只是 warning；`api_version` 是字符串成员测试，`api_version: 1`（JSON 整数）会被判「必须是文本」，而社区写法恰恰是整数。

**方案：双档清单，按 `api_version` 分档。**

- `api_version` 归一为**整数**：接受 `1`、`"1"`、`1.0`（整数等值），拒绝 `"1.0"`、`1.5`、`true`、`null`。
- `api_version: 2` → **严格档**：13 个字段全部必填，缺任何一个都是 error。
- `api_version: 1` 或缺失 → **兼容档**：维持现状（`id`/`name`/`version` 必填，其余 warning）。
- 宿主支持 `{1, 2}`；`api_version` 不在集合内 → `status='incompatible'`（已有逻辑保留）。
- 13 个必填字段（严格档）：`id` `name` `version` `entry` `author` `description` `api_version` `requires` `data_policy` `native` `side` `upstream` `capabilities`。
- `capabilities` 在严格档必须是非空列表（当前 2 个种子包是 `[]`）。

**为什么用双档而不是一刀切**：一刀切会把已装的三方包全部判死，而用户机器上 `custom_plugins` 是空的、种子包全是 `api_version: "1"`。双档让新标准可强制、老包不炸，且迁移路径明确（把 `api_version` 改 2、补 5 个字段即可）。

**迁移**：10 个种子包全部升到 `api_version: 2` 并补齐 13 字段；`tools/make_plugin_packs.py` 同步改。

**验收**：
- `api_version: 2` 缺任一字段 → `ok=False`，错误文案含「严格档」与该字段名
- `api_version: 2` 且 13 字段齐全 → `ok=True`
- `api_version: 1` 缺 `author` → 仍 `ok=True` + warning（存量行为不变）
- `api_version: 1`（int）与 `"1"`（str）都通过；`"1.0"` / `1.5` / `true` / `null` 全部拒绝
- 10 个种子包全部 `ok=True` 且 `meta['api_version'] == 2`

### 1.3.104 — 竞标-仲裁

**问题**：`plugin_dispatch.py` 每个钩子都是 `for plugin in tuple(self._plugins.values())` 顺序执行，先到先得。同一能力（比如两个插件都要回一句话）谁先注册谁赢，用户无从知道为什么。

**方案**：
- 插件清单/`PluginMeta` 增加 `capability_weight: int`（默认 0）与 `capability_exclusive: bool`（默认 False）。
- 对**排他能力**（`exclusive=True`，例如「生成回复」`generate`），先收集所有候选的竞标，按 `(weight, 注册顺序)` 排序，只执行权重最高的一个，其余记 `lost_bid` 不执行。
- 对**非排他能力**（默认，例如 `on_observed` 记录消息），全部执行，不仲裁。
- 仲裁结果写进 `runtime.bid_trace`（list of dict：`{hook, winner, weight, losers:[{id,weight}], reason}`），供控制台展示与日志。

**为什么需要**：用户截图里问「一个回话关联到四五个插件，最后只调用最主要的那个，那其他插件真的有用吗」——这正是要回答的问题。仲裁必须留痕，否则就是黑箱。

### 1.3.105 — 权限五项 + 执行前校验

**问题**：清单有 `permissions` 字段，`load_manifest` 解析成列表，但**从不检查**。插件声明 `permissions: []` 和声明 `permissions: ["net","fs_write"]` 在运行期完全一样。

**方案**：五项权限 `net` / `fs_read` / `fs_write` / `exec` / `wechat_send`。
- 插件在 `PluginMeta.permissions` 声明；未声明即**没有**任何权限。
- 宿主提供 `runtime.guard.require('net')`，插件做对应动作前必须调用；未声明时抛 `PermissionDenied`，`plugin_dispatch.protected()` 记一次故障并跳过该插件本轮。
- 执行前校验：`PluginDispatch` 在每个钩子调用前把插件声明的权限集注入 `runtime` 的一个只读视图，插件拿到的是**能力受限门面**而不是全量 `runtime`。

**为什么**：截图第 3 条标准说「靠了也能装，但必须标出来，把代价写在明面上」。权限就是那个「明面上」。

### 1.3.106 — 数据命名空间 + data_policy

**问题**：`state_file()` 已按 `state_dir/<id>` 隔离，但 `data_policy` 只是给人看的字符串，没有任何强制。插件理论上可以往任意路径写。

**方案**：
- `data_policy` 升为结构化枚举：`none` / `own_settings` / `own_state` / `chat_content` / `external_network`，可多选，写进清单。
- `state_file()` 之外新增 `data_dir()`，只返回 `state_dir/<id>/` 下路径，任何 `..` 逃逸直接抛。
- 卸载时按 `data_policy` 决定是否连数据一起删（`chat_content` 需二次确认）。

### 1.3.107 — 卸载清干净

**问题**：现在只有「禁用」和 `set_removed`（记住别再装），`remove_pack` 只删目录。设置残留在 `plugin_settings.json`，状态残留在 `state_dir/<id>/`，重装后「老设置又回来了」。

**方案**：
- `remove_pack` 增加 `purge` 参数（默认 False 保持现状）。
- `purge=True` 时同时清：`plugin_settings.json` 里该 id 的键、`state_dir/<id>/`、`custom_plugins.json` 里的登记。
- 控制台提供「卸载（保留数据）」与「彻底卸载（连数据）」两个按钮。
- 验收：装 → 改设置 → 写状态 → 彻底卸载 → 重装 → 设置是默认值、状态文件不存在。

### 1.3.108 — 三个挂载点收敛

**问题**：8 个钩子平铺，插件作者不知道该实现哪个，也说不清「这个插件在链路的哪一步」。

**方案**：收敛为三个挂载点，旧钩子保留为内部转发（不破坏存量）：
- `observe`（观察）→ 吸收 `on_ingest` / `on_observed` / `on_block`
- `compose`（组装）→ 吸收 `on_pre_ai` / `on_prepare` / `generate`
- `settle`（收尾）→ 吸收 `on_sent` / `on_post_reply` / `tick`

新插件只实现三个之一；`PluginBase` 提供默认转发，老插件零改动。

### 1.3.109 — 人格独立记忆 + 日记周期 + 心情重置

用户截图里的原话：

> 我是更偏向于只保留主人格的情况下，其他的人格只有在特定的聊天中才会出现，然后主人格为之为基本的，所有的日记都是以主人格为主，这样以日记的方式保留了记忆，而其他人格的记忆，会单独再另外的文件夹里面保存，每个人格只会读取相应文件夹的记忆，然后日记每存储一周会删除一次，只留取重要的内容或者关键词，这个记到每个月清理一次的月记中，同样出现频率最多的事情会一直保留。然后心情方面，每天心情会 4 小时不聊天随机重置一次，然后根据主人的 3 次绘画中 u 定心情，对只有主人的回话有用。

拆成四条：
1. **主人格为基**：所有日记写到主人格目录，其他人格只在特定聊天出现。
2. **人格独立记忆目录**：`data/personas/<persona>/memory/`，每个插件/人格只读自己那份，跨人格读取直接拒绝。
3. **日记周期**：周记（7 天）→ 提炼成关键词与重要条目 → 汇入月记（每月清理一次）；高频事件永久保留（频率阈值可配）。
4. **心情重置**：4 小时不聊天则随机重置；主人 3 次绘画/对话可定向设定；**只对主人回复生效**。
