# DSH与微信后台接入核查（1.3.2）

用户要求参考[qq-bridge](https://github.com/Derpyu520/qq-bridge)和[ctw微信项目](https://github.com/ctw07/ctw-s-deepseek-wechat-chat-bot)，允许简化功能，但保留基础收发、记忆和安装升级行为。

## 查到什么

qq-bridge提交a49877f4e58d04e47532d44b803360d0f001160d，MIT；重点核查src/dsh-client.js、src/bridge.js和plugins/qq-agent-presets。它把会话、模型选择、事件流、最终回复及工具权限分开；本次按公开协议原生实现Python桥，没有运行QQ进程或搬入整个QQ插件框架。DSH协议涉及Cookie authority签名、client-request/server-response信封、斜杠RPC及remote.mux的item/snapshot/event。协议会随DSH版本变化，必须检测，不能只测端口。

ctw项目提交0482b258966ea0449e2fdc4cd3d9bbb0ccbfe685当前树只公开README和LICENSE，链接到视频教程；没有可审阅的发送代码。因此不能据此认定微信4.x能锁屏/最小化/跨会话后台发消息，也没有移植来源不明的二进制。

本机从现有qq-bridge配置只读确认DSH地址不同于默认3080，原生客户端对settings/describe和agentPresets/list检测成功。未复制配置密钥、未保存浏览器签名密钥。检测本机仍是0.1.5目录机制，已安装自己的whale-wechat-chat目录人设，不改profile、不重启DSH。最小问答实测3.81秒；合成数据连续两轮正确记住茉莉茶（3.84/2.19秒），另一个群会话回答未提供（2.80秒）。这些没有发送微信消息，也没上传私人历史；测试会话已归档。

## 实际实现

DSH默认关闭，在Agent页绑定管理员后打开“DSH对话引擎”。使用自己的零工具人设；检测依赖后区分旧版目录人设和新版profile行，未知机制不修改。修改前备份，只处理自己的文件/行，其他插件保留，不自动重启DSH。无工具人设同时以restrict({allow:[]})屏蔽继承工具，guard拒绝全部执行。它负责生成对话，不拥有微信发送或电脑操作工具。QQ/桌面管理端仍可用原有带范围凭据的控制面，不能从群消息开启DSH设置。

微信已触发消息 → 原本地历史/记忆/识图链 → DSH独立会话 → 完整turn/end → 原回复整理/@抑制 → 原transport。消息触发、白名单、25秒发送不重发及故障插件隔离保留。缺少专用人设不使用默认编码Agent代替。失败不重复问DSH、不转原API补问；尝试清本会话inbox和取消回合，未确认取消仍标uncertain且不复用，不触碰其他QQ/桌面会话。

SQLite dsh_sessions按地址/模型、模式、账号、群/私聊、人设正文及管理员绑定版本映射，最多500条映射；初次播种有界近期上下文，此后只带当前问题与本地人设/记忆提示，不重传整段历史。活动会话20轮后换新，原DSH会话、本地原始聊天不删除。个人偏好不会跨群/账号混用。

保留学习库每会话1000条活动窗口、证据化事实/表达候选和批准后提示增强。它是本地记忆学习，不是修改API模型权重。本版没有自动联网研究、日记调度、跨QQ共享全部记忆或桌面Agent执行链；这些不能用“已连接”冒充完成。可观察执行阶段和最终结果，不保存/转发内部推理正文。

## 验证边界

离线测试覆盖Cookie签名、RPC信封、快照与分块隔离、完整答复、重复事件、按会话隔离、历史只播种一次、设置改变后丢弃旧结果、失败取消不重问、原发送闸门与@清理。冻结自检覆盖DSH解析器/依赖/临时profile安装。真实DSH已完成最小问答、合成多轮上下文和跨群隔离验证；没有真实微信发送。最初一次问答暴露AUTH：QQ实际使用自定义提供商而非官方，修复为provider/model/reasoningEffort分别配置后通过。GUI可只读导入qq-bridge接入参数，不复制authToken或API Key、不自动启用。

后续验收需按界面步骤保存用户实际地址/提供商/profile，必要时手动重启DSH，再分别验证用户人设、记忆与微信发送；后台posted_enter仍需单独实际授权和验收。缺UIA控件时增加DSH或图片插件不会改变底层可用性。
